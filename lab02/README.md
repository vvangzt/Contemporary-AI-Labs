## 1. 项目概览

本实验围绕两类经典搜索算法展开：

| 算法 | 用途 | 涉及题目 |
| --- | --- | --- |
| A*（A-star） | 单源最短路径，带启发函数的有序搜索 | 题目一、题目二、题目四（距离预计算） |
| Minimax / Alpha-Beta | 双人零和博弈树的对抗搜索 | 题目三、题目四（决策层） |

实现上的核心主张是：**四道题共享同一套搜索内核**，各题只在“邻接关系、进入代价、启发函数”三处产生差异。因此代码结构是：

```
search_core.py   通用 A* / 单源最短路 / 双向 BFS
    ├── t1.py    题目一：把「四邻接 + 每步代价 1 + 曼哈顿距离」接进去
    ├── t2.py    题目二：把「四邻接 + 进入代价=地形权值 + 修正启发」接进去
    └── t4.py    题目四：把「四邻接 + 进入代价=地图权值」接进去算距离矩阵，再叠加博弈层
        t3.py    题目三：独立的博弈树实现（树结构由题目给定，无需栅格搜索）
bench.py         规模实验、时间指标、图表生成
figs/            报告用图表
results_*.csv    bench.py 导出的原始数据
```

> 初版代码里 t1、t2、t4 各有一份几乎相同的 A*（约 60 行 × 3）。本版收敛为一份，减少了三份代码行为不一致的风险，也让所有对照实验都在同一实现上进行。

## 6. 算法设计

### 6.1 统一的 A*：状态、代价、启发与数据结构

**状态**：格点坐标 `(row, col)`。**代价**：进入某格的代价值（题目一恒为 1，题目二/四取地形权值）。
**评价值**：`f(n) = g(n) + h(n)`，其中 `g` 是从起点到 n 的已付代价，`h` 是到终点的估计剩余代价。

**数据结构**（`search_core.astar`）：

| 结构 | 类型 | 作用 |
| --- | --- | --- |
| `open_heap` | 最小堆 `(f, tie, counter, node)` | 按 f 取最优；`counter` 为自增序号，避免节点不可比较时崩溃，同时保证同分节点先进先出 |
| `g_score` | `dict[node -> cost]` | 记录已知最小 g，用于松弛 |
| `parent` | `dict[node -> node]` | 记录前驱，用于回溯路径 |
| `closed` | `set[node]` | 已扩展集合，防止重复扩展 |

**主循环**：

1. 弹出 f 最小的节点；若已在 `closed` 中则跳过（懒删除，堆里可能存在同一节点的旧条目）。
2. 加入 `closed`；若为目标，沿 `parent` 回溯并返回 `(g, path, len(closed))`。
3. 对每个邻居计算 `ng = g(u) + step(u,v)`；若 `ng < g_score[v]`，更新 g、前驱并压入堆，键为 `ng + h(v)`。
4. 堆空仍未到达则返回 `(INF, [], 扩展数)`。

**为什么闭集可以不回开**：题目一/二使用的启发（曼哈顿、`max(0, 曼哈顿-1)`、h=0）都是**一致（consistent）** 的，
即对任意相邻 `u, v` 满足 `h(u) - h(v) <= c(u, v)`。满足一致性时可证明节点第一次出堆即已最优，
无需重新打开。题目二的修正启发一致性推导见 6.2。

**复杂度**：设节点数 V、边数 E，堆操作 O(log V)，故 A* 为 `O(E log V)`；栅格图 E ≈ 4V。

**平局打破（节点排序优化）**：当 `f` 相同时，优先扩展 `g` 更大（更接近目标）的节点。
实现上把堆键的第二位设为 `-g`，即 `(f, -g, counter, node)`。
该策略不改变最优性（只改变同层节点的展开次序），但能把搜索前沿压向目标一侧。

> 默认 `tie_break=False`。这样题目一、二的主流程输出与给定用例**逐字一致**；
> 打开后用于对照实验。这是一个刻意的取舍，见第 11 节。

### 6.2 题目二的启发函数：为什么原始曼哈顿不可采纳

设从某格 n 到终点 E 的一条最优路径有 k 步。按规则，前 k−1 步每步进入代价不小于 1（最便宜的地形是 1），
最后一步进入 E 的代价为 0，因此：

```
h*(n) >= (k - 1) * 1 + 0 = k - 1
```

而曼哈顿距离 `m(n)` 是步数的下界：`m(n) <= k`。两者相减：

```
m(n) - h*(n) <= k - (k - 1) = 1
```

也就是说原始曼哈顿距离最多比真实剩余代价**高估 1**，在 E 的相邻格上（`m=1`、`h*=0`）高估恰好发生，
所以它**严格不可采纳**。修正方式：

```
h(n) = max(0, m(n) - 1)
```

**一致性验证**：相邻两格的曼哈顿距离相差 1，故 `h` 至多变化 1，而每步代价不小于 1，
满足 `h(u) - h(v) <= c(u, v)`；进入 E 的一步 `h` 已降为 0，同样满足。

**为什么不修正也常常“看起来没错”**：高估量只有 1，而题目地图的所有可行步代价都是整数且 ≥1，
A* 仍可能（在构造出的反例上）返回次优解。本项目用 500 张随机地图做了压力测试（第 8.8 节），
结果是 0 例次优——这说明的是**在这个代价结构下**高估被 E 的 0 代价抵消，而**不是**说明原始曼哈顿可采纳。
一旦地图中出现其它 0 代价格子，或代价出现小数，结论立即失效。

### 6.3 Minimax 与 Alpha-Beta

**Minimax**：MAX 层取子节点最大值，MIN 层取最小值，递归到底返回叶值（题目三）或当前 U（题目四）。

**Alpha-Beta**：维护两个边界

- `alpha`：MAX 已能保证的下界；
- `beta`：MIN 已能保证的上界。

MAX 层每取到一个值就抬升 `alpha`；MIN 层每取到一个值就压低 `beta`。
一旦 `beta <= alpha`，说明该节点的父层已有更好的选择，剩余兄弟分支不可能改变祖先决策，**剪枝**。

```
MAX:  value = max(value, child);  alpha = max(alpha, value);  if (alpha >= beta) break;
MIN:  value = min(value, child);  beta  = min(beta,  value);  if (beta  <= alpha) break;
```

**复杂度**：分支因子 b、深度 d 时，Minimax 为 `O(b^d)`；Alpha-Beta 最好情况 `O(b^(d/2))`，
最坏情况退化为 `O(b^d)`。最好情况需要“最优顺序”的访问次序，即每层先评估最强的动作。

**访问顺序实验的三种模式**（`t3.alpha_beta_search` 的 `order_mode`）：

| 模式 | 行为 | 用途 |
| --- | --- | --- |
| `natural` | 按子节点生成顺序（左→右） | 基准 |
| `reverse` | 逆序 | 对照 |
| `oracle` | 按子树真实博弈值排序（MAX 降序 / MIN 升序） | 理论上界，需 `true_values` |

> `oracle` 需要先用一次完整 Minimax 预计算所有节点的真值（`compute_true_values`），
> 这在实际搜索前是不可能获得的，因此它只用于**刻画上界**，不能当作可用算法。

### 6.4 题目四的博弈建模

**状态**（`GameState`）：

| 字段 | 含义 |
| --- | --- |
| `pos_A` / `pos_B` | 双方当前所在位置（`'A'`、`'B'`、`'T1'`~`'T8'`） |
| `remaining_treasures` | 剩余宝藏的元组 |
| `score_A` / `score_B` | 双方累计净收益 |
| `current_player` | 当前行动方（`'A'` 为 MAX，`'B'` 为 MIN） |
| `values` | 宝藏价值表（拓展实验可替换） |

**单步转移**：选择宝藏 `t` 后，行动方支付 `d(p, t)` 的路程代价、获得 `V[t]`，位置更新为 `t`，
剩余集合删去 `t`，行动方切换。收益差增量：

```
A 行动:  U 增量 = + (V[t] - d(pos_A, t))
B 行动:  U 增量 = - (V[t] - d(pos_B, t))
```

**评价值**：`U = Score_A - Score_B`。A 最大化 U，B 最小化 U，因此这是一个零和博弈。

**距离矩阵**：`d(p, q)` 由 `compute_distance_matrix` 用单源最短路一次求出整行，
6 个关键点共 6 次调用（初版逐对 A* 为 36 次）。矩阵在本图中对称，
**但这是题目地图的特殊性质**（所有关键点所在格的进入代价都是 1），一般加权图并不对称，
所以实现按“每个源点单独求一遍”的方式写，不假设对称。

**为什么矩阵能直接查表**：博弈每步的移动代价只取决于起点与目标两格，与其它玩家的位置无关
（规则明确“另一玩家不阻挡寻路”），所以可以把移动抽象成一次代价结算，状态里不必保存中间路径。

**置换表缓存的关键设计**（`minimax_cached`）：缓存键为
`(pos_A, pos_B, remaining_treasures, current_player)`，**不含累计得分**。
原因是缓存的是“自当前局面起的**未来**收益差”，而历史得分不影响未来最优决策，
因此同一局面无论从哪条路径到达，未来值都一样。函数返回未来值，总 U = 当前 U + 未来值。

若把累计得分写进键，缓存命中率会趋近于 0（每条路径的得分都不同），这也是初版没敢做缓存的原因。
控制变量做对了，缓存才有意义。

## 7. 题目详解

### 7.1 题目一：迷宫寻路

**接口**

```python
a_star_maze(start, end, grid, use_heuristic=True, tie_break=False) -> (path, expanded)
solve_maze(start, end, grid) -> path          # 对外输出接口
```

**实现要点**

- 邻接：上下左右四方向，越界或 `'X'` 跳过，进入代价恒为 1；
- 启发：`use_heuristic=True` 用曼哈顿距离，`False` 用 0（等价 Dijkstra）；
- 边界：起点/终点越界或落在 `'X'` 上直接返回 `([], 0)`；
- 无解：堆耗尽返回 `([], 扩展数)`。

**测试与结果**

| 指标 | 值 |
| --- | --- |
| 路径 | `(0,0)→(0,1)→(0,2)→(1,2)→(1,3)→(1,4)→(2,4)→(3,4)` |
| 步数 | 7 |
| A*（曼哈顿）扩展节点 | 14 |
| h=0（Dijkstra）扩展节点 | 17 |
| 平局打破扩展节点 | 14（小图无变化） |
| 起点被围死 | `([], 1)` |
| 终点为障碍 | `([], 0)` |

**分析**：`f = g + h` 在最优路径上恒为 7，启发把扩展限制在朝向终点的窄带内。
本题地图只有 17 个可达格，Dijkstra 全扩 17 个，A* 扩 14 个，差距不大——
障碍密集时启发指引会暂时失效，同层节点 `g` 相同且 `f` 并列，排序优化的空间也随之变小。
规模效应在第 8.4 节的 51×51 随机图上才充分体现。

### 7.2 题目二：加权地形

**接口**


### 7.3 题目三：Alpha-Beta 剪枝

**接口**

```python
get_best_score(root: TreeNode) -> int          # 对外输出接口
alpha_beta_search(node, alpha, beta, is_maximizing, stats=None,
                  order_mode="natural", true_values=None) -> int
```

**数值回传过程**（题目测试树）：

```
叶层：            3  5    6  9    1  2
第三层 MAX：       5        9        2
第二层 MIN：          5         2
根 MAX：                 5
```

**剪枝依据**：任一节点满足 `beta <= alpha` 就剪掉剩余兄弟——这意味着“再往下算也不可能改变祖先的决定”。
本题树的剪枝发生在 `MIN1` 的第二个子树 `MAXb` 内部：

1. `MIN1` 先评估 `MAXa(3,5)` 得到 5，于是 `MIN1` 的 `beta = 5`；
2. 评估第二个子树 `MAXb(6,9)` 时，`beta = 5` 被传入；`MAXb` 取到第一个叶值 6 后 `alpha = 6`；
3. 此时 `beta(5) <= alpha(6)`：`MAXb` 的返回值不可能小于 6，而 `MIN1` 已有更小的 5，
   所以第二个叶（值 9）无需评估。

本题共剪 1 个叶节点。

| 指标 | 值 |
| --- | --- |
| 最佳得分 | 5 |
| Alpha-Beta 访问节点 | 14 |
| 纯 Minimax 访问节点 | 15 |
| 剪枝分支数 | 1（叶 9 在 `MIN1` 分支下被跳过） |
| 开销压缩率 | 6.67% |
| 正序 / 逆序访问节点 | 14 / 14 |
| JSON 输入构造后求解 | 5 |

> 注意：题目给的结构里 `max2` 被 `min1` 与 `min2` **共享**（见题目给定的结构），
> 因此它不是严格意义上的树而是 DAG。`min2` 分支会再次完整评估 `max2`：
> 叶 6 被访问两次；叶 9 只在第二次评估中被访问，第一次评估时它被剪掉。
> 这解释了为什么“访问 14 个节点”与“剪掉 1 个叶节点”可以同时成立。

**分析**：测试树只有 4 层、每层 2 个分支，剪枝窗口极小，压缩率仅 6.67%；
访问顺序在这个规模上还没有发挥作用（正逆序都是 14）。这恰好说明：
**“剪枝有没有用”和“顺序有多重要”都依赖树的规模与分支结构**，不能只在小例上下结论。
为此补充了随机树规模实验（第 8.3 节）。

### 7.4 题目四：宝藏分配

**接口**

```python
compute_distance_matrix(locations=None, grid=None) -> (matrix, calls)
GameState(pos_A, pos_B, remaining_treasures, score_A=0, score_B=0,
          current_player="A", values=None)
minimax(state, depth, max_depth, dist_matrix, stats) -> (value, action)
alpha_beta(state, depth, max_depth, alpha, beta, dist_matrix, stats,
           reverse_order=False) -> (value, action)
get_principal_variation(state, max_depth, dist_matrix) -> list[str]
```

**距离矩阵**（6×6，对称）：

|     | A  | B  | T1 | T2 | T3 | T4 |
| --- | --- | --- | --- | --- | --- | --- |
| A   | 0  | 12 | 10 | 4  | 8  | 8  |
| B   | 12 | 0  | 8  | 8  | 4  | 10 |
| T1  | 10 | 8  | 0  | 6  | 6  | 12 |
| T2  | 4  | 8  | 6  | 0  | 6  | 6  |
| T3  | 8  | 4  | 6  | 6  | 0  | 6  |
| T4  | 8  | 10 | 12 | 6  | 6  | 0  |

**H=2 与 H=4 的结果**

| 深度 | 算法 | 最优首步 | 最优收益差 | 访问节点 | 剪枝分支 | 压缩率 |
| --- | --- | --- | --- | --- | --- | --- |
| H=2 | Minimax | T2 | −1 | 17 | — | — |
| H=2 | Alpha-Beta（正序） | T2 | −1 | 13 | 4 | 23.53% |
| H=2 | Alpha-Beta（逆序） | T2 | −1 | 16 | 1 | — |
| H=4 | Minimax | T3 | 3 | 65 | — | — |
| H=4 | Alpha-Beta（正序） | T3 | 3 | 47 | 6 | 27.69% |
| H=4 | Alpha-Beta（逆序） | T3 | 3 | 46 | 5 | — |

**主变例与决策分析**

```
H=2:  A 取 T2 (U=2) → B 取 T3 (U=-1)
H=4:  A 取 T3 (U=-1) → B 取 T1 (U=-2) → A 取 T2 (U=-2) → B 取 T4 (U=3)
```

- **H=2**：两层视野内 A 只看自己的净收益。T2 距离 4、净得 2，是四个宝藏中对自己最划算的；
  但 A 预见不到 B 随后会抢走对 B 最有利的 T3（距离 4、净得 3），最终 U = −1。
- **H=4**：A 首步远征中心宝藏 T3，自身净收益为负（7−8=−1），
  却消除了 B 的最优目标，迫使 B 在终局只能拿 T4（距离 12、净亏 5），U 反转为 3。

**结论**：深度从 2 增至 4，最优首步由 T2 变为 T3。浅层贪心不等于深层最优，
博弈搜索的价值正在于把对手的理性回应纳入计算。

**剪枝顺序的细节**：H=2 时正序（13）明显优于逆序（16），因为正序下根节点第一个评估的恰好是
最优的 T2，`alpha` 迅速收紧；H=4 时逆序（46）反超正序（47），因为先评估的动作更早暴露强约束。
两个深度给出相反的排序结论，说明剪枝效率依赖具体局面的值分布，不存在普适最优顺序。

### 8.3 访问顺序的影响

**A. 题目测试树（小规模）**

| --- | --- | --- | --- |

**B. 自设随机树（D 深度、b 分支、叶值 0~30、seed=42）**

| 配置 | 整树规模 | 纯 Minimax | AB 自然序 | AB 逆序 | AB oracle | 根值 |
| --- | --- | --- | --- | --- | --- | --- |
| D=6, b=3 | 1093（叶 729） | 1093 | 433 | 465 | **125** | 13 |
| D=4, b=5 | 781（叶 625） | 781 | 232 | 320 | **93** | 8 |
| D=8, b=2 | 511（叶 256） | 511 | 275 | 279 | **98** | 12 |

**读法**：

- 纯 Minimax 的访问数恰好等于整树节点数 `(b^(D+1)-1)/(b-1)`，可作为正确性校验；
- 自然序压缩 46%~70%（D=6,b=3：60.4%；D=4,b=5：70.3%；D=8,b=2：46.2%）；
- oracle 最优序再降一个数量级（1093→125，约 1/8.7），与理论最好情形 `O(b^(D/2))` 同阶；
- 逆序略劣于自然序，但在 D=4、b=5 时差距最大（232 vs 320，差 38%），
  说明分支因子越大，顺序的影响越明显。

### 8.4 A* 随地图规模的变化（bench.py 基准一）

每档 3 张随机图（25% 障碍，seed=0/1/2）取均值，起点 `(0,0)`、终点 `(n-1,n-1)`：

| 边长 n | 最短步数 | Dijkstra | A*（曼哈顿） | A* + 平局打破 | 双向 BFS | A* 耗时(ms) |
| --- | --- | --- | --- | --- | --- | --- |
| 11 | 20 | 93 | 81 | 28 | 66 | 0.09 |
| 21 | 40 | 324 | 145 | 58 | 214 | 0.16 |
| 31 | 60 | 721 | 409 | 106 | 533 | 0.45 |
| 41 | 80 | 1271 | 726 | 132 | 1032 | 0.79 |
| 51 | 100 | 1950 | 1008 | **274** | 1536 | 1.12 |

**结论**：

1. 51×51 上平局打破让扩展节点从 1008 降到 274（−72.8%），且从 11 到 51 每一档都有效；
2. 双向 BFS 是 A* 的 1.52 倍——它不使用启发，两端各自扩展一个“圆盘”，
   总面积超过单向沿目标方向展开的窄带。这是“看似合理但实测更差”的典型反例；
3. Dijkstra 与 A* 的差距随规模扩大而拉大（93/81 → 1950/1008），启发函数的相对收益随搜索空间增长。

### 8.5 博弈搜索随宝藏数量的变化（bench.py 基准二）

在 7×7 地图上逐步增加宝藏（T5~T8 落在原本代价为 1 的空地），深度取宝藏数（完整对局）：

| 宝藏数 | 博弈值 | 纯 Minimax | +置换表 | 缓存命中 | Alpha-Beta | 剪枝分支 |
| --- | --- | --- | --- | --- | --- | --- |
| 4 | 3 | 65 | 65 | 0 | 47 | 6 |
| 5 | 1 | 326 | 266 | 60 | 154 | 35 |
| 6 | 4 | 1957 | 997 | 420 | 355 | 116 |
| 7 | −2 | 13700 | 3410 | 1890 | **1386** | 471 |

**相对于纯 Minimax 的节点降幅**

| 宝藏数 | 置换表 | Alpha-Beta |
| --- | --- | --- |
| 4 | 0.0% | 27.7% |
| 5 | 18.4% | 52.8% |
| 6 | 49.1% | 81.9% |
| 7 | 75.1% | 89.9% |

**结论**：

1. **缓存在 4 宝藏时完全无效**：4 个宝藏只有 4 步，状态是“排列前缀”，
   几乎没有两条不同顺序汇合到同一（剩余集合, 双方位置, 行动方）的情况，命中 0 次。
2. 宝藏增至 7 个，不同顺序开始大量汇合，缓存命中 1890 次，节点降 75.1%。
3. **Alpha-Beta 始终更强**：7 宝藏只需 1386（降 89.9%），少于缓存的 3410。
   原因是剪枝直接剪掉整棵不可能影响结果的子树，而缓存只是复用已经算过的节点。
   两者的适用条件不同：状态重复多时选缓存，分支有序性好时选剪枝。
4. 三种算法在所有规模上求得的**博弈值完全一致**（脚本内 `assert` 校验），
   说明优化没有改变结果，只改变了开销。

### 8.6 搜索深度 2×2 对抗（t4.depth_match_experiment）

随机生成 200 组宝藏价值（1~9，seed=7），A、B 各用固定深度搜索完整对局：

| 组合（A 深度 − B 深度） | 平均 U | A 胜率 | A 负率 | 平局率 |
| --- | --- | --- | --- | --- |
| 2 − 2 | +5.650 | 88.0% | 8.5% | 3.5% |
| 2 − 4 | +4.520 | 87.5% | 8.5% | 4.0% |
| 4 − 2 | +6.350 | 99.0% | 0.0% | 1.0% |
| 4 − 4 | +5.090 | 97.5% | 0.0% | 2.5% |

**边际效应**：

- B 固定在深度 2，A 从 2→4：平均 U 5.650 → 6.350（**+0.70**），胜率 88.0% → 99.0%（+11 个百分点）；
- B 固定在深度 4，A 从 2→4：4.520 → 5.090（**+0.57**），胜率 87.5% → 97.5%（+10 个百分点）；
- A 固定在深度 2，B 从 2→4：A 的 U 5.650 → 4.520（**−1.13**）；
- A 固定在深度 4，B 从 2→4：6.350 → 5.090（**−1.26**）。

**结论**：自己加深只多得约 0.6，对手加深却让你损失 1.1~1.3。
博弈中“防守方的深度”更值钱——深搜的对手会系统性地利用你的短视。
另外注意 A 的基准胜率本来就高（先手优势），所以比较必须看**同条件的边际变化**，不能只看绝对值。

### 8.7 截断评估函数的边界（t4 拓展 3）

| 设置 | 首步 | 评价值 |
| --- | --- | --- |
| 完整博弈 H=4（真值） | T3 | 3 |
| H=2 裸截断 | T2 | −1 |
| H=2 + 潜在收益评估 | **T2** | **3** |

评估函数按“谁离宝藏更近”贪心分配剩余宝藏的潜在净收益：

```
对每个剩余宝藏 t：
    dA = d(pos_A, t), dB = d(pos_B, t)
    若 dA <= dB：潜在收益 += max(0, V[t] - dA)
    否则：      潜在收益 -= max(0, V[t] - dB)
```

**结论**：评估把分数从 −1 修正到 3（与真值相同），但**首步仍然是 T2**。
数值估计变准了，策略却没变——因为 H=2 下 A 根本没有计算 B 的回应，
而 T3 的价值恰恰来自“堵住 B 的最优目标”这一层博弈。
这组对照说明：**评估函数改善的是对局面的估计，替代不了对对手回应的计算**，视野不足必须靠加深搜索解决。

### 8.8 可采纳性压力测试（t2.stress_test_admissibility）

| 项目 | 设置 |
| --- | --- |
| 样本 | 500 张随机 6×6 加权地图 |
| 格子代价 | 1~9 均匀分布 |
| 起点/终点 | 随机选取（互不相同） |
| 基准 | h=0（Dijkstra，必然最优） |
| 判据 | 原始曼哈顿 A* 返回的代价 ≠ 基准代价 |
| 结果 | **0 例次优**（seed=0） |

**如何解读**：这不是“原始曼哈顿安全”的证据，而是“在这个特定代价结构下高估被抵消”的证据。
把地图改成含 0 代价格子、或让某些地形代价小于 1，结论立刻不同。
工程建议：始终使用 `max(0, 曼哈顿-1)`（或更紧的下界），不要把“实验没出错”当成“理论有保证”。

### 8.9 工程优化：距离矩阵的单源化

| 方式 | 搜索调用次数 | 结果 |
| --- | --- | --- |
| 初版：逐对 A* | 6×6 = 36 次 | 正确但冗余 |
| 本版：每源点一次单源最短路 | **6 次** | 逐项一致（脚本校验） |

正确性来源：单源最短路给出源点到**所有**节点的最优距离，因此一次调用即可填满矩阵的一整行。
`compute_distance_matrix` 返回 `(matrix, calls)`，`calls` 用于在输出中直接展示这一改进。

> 注意：本矩阵对称，是因为题目地图中所有关键点所在格的进入代价都是 1。
> 一般加权图上 `d(u,v) ≠ d(v,u)`（起点侧不付代价、终点侧要付），实现因此不假设对称。

## 11. 设计决策与取舍

### 11.1 为什么平局打破默认关闭

打开后题目一、题目二的扩展节点数会变化（题目二 11→9），最坏情况下还可能返回**另一条等长路径**。
虽然题目明确“可能存在多条相同长度最短路径，输出任意一条即可”，但为了让提交结果与测试用例
逐字对照（便于助教核对），主流程保持 `tie_break=False`，优化项作为显式参数用于对照实验。
需要时一行即可打开：

```python
path, expanded = a_star_maze(start, end, grid, tie_break=True)
cost, path, expanded = solve_weighted_maze(start, end, grid, tie_break=True)
```

### 11.2 为什么闭集不回开

所有使用的启发都满足一致性（见 6.1、7.2），节点首次出堆即最优，无需重新打开。
若将来换成不可采纳的启发（例如加权 A*），必须改为允许重开，否则可能返回次优解。

### 11.3 为什么不做双向 A*

实现了双向 BFS 作为对照（`search_core.bidirectional_bfs`），实测在 51×51 上是 A* 的 1.52 倍。
原因是缺乏方向性：两端各自扩展一个半径减半的圆盘，总面积大于单向的窄带。
要发挥双向的优势，需要**双向都带启发**，并且两侧的启发都要可采纳；
这在本题规模上收益有限，因此只保留为反例分析，不进入主流程。

### 11.4 为什么缓存键不含累计得分

缓存的是“未来收益差”，未来最优决策只取决于（双方位置, 剩余宝藏, 行动方）。
若把累计得分写进键，命中率会接近 0。这个设计用一次 `assert` 校验过：
有缓存与无缓存求得的博弈值完全一致（4/5/6/7 宝藏全部通过）。

### 11.5 为什么 Alpha-Beta 不做置换表

Alpha-Beta 的置换表需要区分“精确值 / 下界 / 上界”三种条目（fail-soft 或 fail-hard 变体），
否则在剪枝窗口下缓存可能被错误复用。本实验规模下缓存收益已被 Alpha-Beta 的剪枝覆盖
（7 宝藏 1386 vs 3410），因此没有实现带边界的 TT。若继续做，应参考
“transposition table with bound flags”的标准实现。

### 11.6 为什么评估函数用贪心分配

潜在收益评估按“谁更近谁拿”做贪心分配，实现简单、可解释。
更严格的做法是把剩余宝藏的分配建模为**指派问题**（匈牙利算法 / 最小费用流），
获得剩余局的乐观上界。但实验目的只是验证“评估能否替代视野”，
贪心版本已经足以得出否定结论（值修正、首步不变），因此没有必要引入更重的算法。

### 11.7 为什么距离矩阵按源点逐行求

虽然本题矩阵对称，但对称性来自“所有关键点入格代价均为 1”这一巧合。
逐行求最短路既不依赖对称性，又能把调用次数从 36 降到 6，是更稳妥的写法。

## 12. 正确性验证

`python verify.py` 把下列检查打包成一次运行；除此之外，代码内部还做了四类校验：

1. **交叉校验（算法等价性）**
   - `bench.experiment_astar` 中断言 `Dijkstra == A* == 平局打破 == 双向 BFS` 的代价一致；
   - `bench.experiment_game` 中断言 `Minimax == Alpha-Beta == 缓存版` 的博弈值一致；
   - `t4` 的 [拓展 1] 打印“值一致=True”，覆盖 4/5/6/7 宝藏。

2. **树规模自校验**
   - 随机树实验中纯 Minimax 的访问数恰好等于整树节点数
     `(b^(D+1)-1)/(b-1)`（1093、781、511 三个配置都吻合），
     这同时验证了树的生成与计数器。

3. **边界用例**
   | 场景 | 题目一 | 题目二 |
   | --- | --- | --- |
   | 起点被障碍完全围死 | `([], 1)` | `(-1, [], 1)` |
   | 终点落在障碍上 | `([], 0)` | `(-1, [], 0)` |
   | 起点等于终点 | `([start], 1)` | `(0, [start], 1)` |

4. **压力测试**
   - 500 张随机加权地图上以 Dijkstra 为基准对拍原始曼哈顿（0 例次优）；
   - 200×4 局随机博弈对局，所有胜/负/平局统计之和为 100%。

## 13. 常见问题

**Q1：`ModuleNotFoundError: No module named 'search_core'`**
在项目根目录运行；或 `sys.path.append(r'...\P2')`。

**Q2：`ModuleNotFoundError: No module named 'matplotlib'`**
只有 `bench.py` 需要：`pip install matplotlib`。四道题不需要任何第三方库。

**Q3：图表里的中文变成方块**
`bench.py` 顶部已设置 `Microsoft YaHei` / `SimHei`。若系统没有这两个字体，
安装 `fonts-noto-cjk` 并把 `"Noto Sans CJK SC"` 加进列表；或临时把标签改成英文。

**Q4：t4 运行较慢**
主要开销在 2×2 深度对抗（200 组 × 4 组合）与 7 宝藏完整搜索（13700 节点）。
调试时可把 `depth_match_experiment(trials=200)` 改成 `trials=20`。

**Q5：`compute_distance_matrix()` 的返回值为什么是元组**
返回 `(matrix, calls)`，`calls` 是单源搜索的调用次数（6），用于在输出中直观展示
“36 次 → 6 次”的改进。只想要矩阵时用 `matrix, _ = compute_distance_matrix()`。

**Q6：`a_star_cost()` 能用于拓展局吗**
不能。它内部用 `LOCATIONS` 判断“特殊格”，只适用于原题地图。
拓展局请用 `compute_distance_matrix(locations, grid)`，它接受任意点集。

**Q7：为什么 `minimax_cached` 的返回值与 `minimax` 不同**
`minimax` 返回**累计** U，`minimax_cached` 返回**未来** U（因为缓存的是未来值）。
初始状态得分为 0 时两者相等；一般状态下满足 `总 U = 当前 U + 未来值`。

**Q8：为什么题目三的逆序有时比正序更快**
剪枝效率取决于“先看到的动作有多强”。H=4 的逆序恰好先评估了强约束（代价差大的动作），
使 beta 迅速下降。这不是逆序更优，而是“本次局面的倒序恰好更接近 oracle 顺序”。

## 14. 已知局限与可继续的方向

### 14.1 已知局限

1. **距离矩阵的对称性**依赖题目地图的特殊结构，推广到一般加权图时需重新审视。
2. **双向 BFS 只支持等权图**，不能直接用于题目二/四的加权场景。
3. **Alpha-Beta 未结合置换表**（需要边界标记的 TT），7 宝藏下缓存（3410）明显弱于剪枝（1386），
   但两者结合的收益未测量。
4. **评估函数是贪心分配**，不是最优指派；理论上界更紧的做法是匈牙利算法。
5. **深度对抗只比较 2 与 4**，未覆盖迭代加深、时间受限搜索（真实对局更常见）。
6. **未做工性能剖析**（`cProfile`），耗时仅按毫秒记录，未分析热点。
7. **随机图生成按连通性重采样**，在障碍率接近渗流阈值时会变慢（本实验 25% 无障碍）。

### 14.2 可以继续做的方向（附预期收益与风险）

| 方向 | 做法 | 预期 | 风险 |
| --- | --- | --- | --- |
| Jump Point Search | 均匀栅格上跳过对称路径 | 开阔图上扩展数大幅下降 | 4 向移动的 JPS 变体实现复杂，需仔细处理对角线规则 |
| 加权 A*（`f = g + w·h`） | w>1 换取速度 | 扩展数下降、路径代价略增 | 不再保证最优，需要画“代价-节点”权衡曲线 |
| ALT 地标启发 | 预计算少数地标距离 | 加权图上下界更紧 | 预处理与存储开销，需选点策略 |
| PVS / NegaScout | 零窗口搜索 + 重搜 | 有序树上前提下减少节点 | 需要对顺序敏感，收益不稳 |
| 迭代加深 + 时间控制 | 逐层加深直到超时 | 更贴近真实对局 | 需要稳定的计时与可中断搜索 |
| Alpha-Beta + 置换表 | 边界标记（exact/lower/upper） | 两者收益叠加 | 实现细节多，容易写错复用条件 |
| 匈牙利评估 | 剩余宝藏最优指派 | 截断估计更准 | 每题节点开销上升，可能在浅层不划算 |
| 可视化 | A* 前沿扩散动画、剪枝树高亮 | 报告表现力强 | 仅影响展示，不影响指标 |

> 需要提醒：本项目的实测已经说明“想当然的优化可能更差”（双向 BFS 1.52×）。
> 继续做任何一项之前，先建对照、固定种子、记录节点数与耗时，再决定是否保留。
